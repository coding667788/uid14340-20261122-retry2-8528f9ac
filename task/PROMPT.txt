给合成软件物料清单做一套组件准入审查。若干制品根共享同一个组件解析环境，每个组件在一次部署中只能选一个已公布版本。版本携带依赖版本闭区间、审批区域、是否需独立复核。任何被选组件的依赖都要递归满足，允许循环但要整圈同时满足版本约束；未从制品根可达的组件不得被当成替换动作，也不计入部署。区域使用规则沿依赖链传播，一个组件服务多个根时必须在每个根的部署区域都获批。同一版本如果需复核，需存在绑定版本和区域的未过期审批。
audit 检查指定部署并给每个违规根的最短依赖见证（同长取 ID 序列最小），区分版本冲突、区域缺批与审批失效。solve 从批准版本中找合法部署，先最小化相对基线改变的组件数（增删改各计一次），再最小化版本替换费用，最后按升序 (组件,版本) 列表决胜。支持 35 组件和每组件 4 版，说明回溯传播、环和不可达组件处理。测试覆盖单根独立可解但多个根不能共用一版、循环及互斥范围、局部便宜导致全局换更多、同版跨区审批、不可达旧组件和小规模完整对照。

把合法最终部署扩成无安全空窗的替换路径。组件有候选版本安装包，输入给出带方向的允许版本迁移边、对应迁移成本和批次原子替换组；单组件迁移或已登记的组迁移是单步，组内同时改变。每一步之后，从任何正在运行的制品根可达的组件都须满足原依赖规则，并通过输入在各阶段列出的隔离区准入政策。特定制品可以被显式暂停再恢复，每暂停一个制品每步付给相应停运成本，且不能暂停超过并发上限；暂停中的制品不可被用来证明服务存在。部分关键能力要求每步至少存在一个运行中的等价根，能力组可能重叠。目标结果是一个计划和最终合法部署，按最终相对原基线的改动组件数、总迁移与停运成本、步数及操作 ID 序列最小化。只有已到达的合法状态允许作为后续状态，不能直接跳到最终解。测试加入单独改一成员就会造成不合法的循环依赖、最终部署合法却无合法路径、允许暂停但关键能力仍需存活、最便宜的最终替换路径因区域审批阶段不同不可用，以及可行前缀和见证独立回放。迁移场景限 16 个组件、各至多 3 个版本，限制步数由输入提供。

从空仓库实现准入审查与替换规划，目标运行环境是只依赖标准库和 CPU 的 Windows 原生 Python 3.12。全部样例及测试夹具使用本地虚构数据。按 `python -m solution <命令> CASE.json` 读取方案，凡涉及持久状态的命令都接受 `--db DB.sqlite`。同一逻辑案例应在标准输出中得到一致的 UTF-8 JSON，结构错误须能通过错误码及字段位置查明。请在 README 定义完整的输入和输出、写出可直接运行样例的复现命令，并以 `python -m unittest discover -s tests -v` 为断言测试入口。
